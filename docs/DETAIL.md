# 插件分类

在「设置 → 插件」页多出一个**分类**标签，把已经装好的插件按用途分组，一眼看清这台机器上装了什么、各自是干什么的。

## 它做什么

- **按用途分组**：视觉与视频、界面与美化、用量与计费、即时通讯、远程控制、金融行情、开发与效率、系统与维护、官方核心、其他。每个分组显示插件数量。
- **识别已装插件**：读取宿主真实的插件清单（`pluginInventory` + `pluginManager.listBundles`），只列已经安装的包；宿主没开插件管理时明确提示，而不是显示空表。
- **就地改分类**：每个插件右侧有一个分类选择器。内置规则认不出来的插件会落进「其他」，在这里选一个合适的分类即可移动；也可以「新建分类」，或者选「自动归类」还原成内置规则。
- **改动可持久**：手动分类存在浏览器本地（`localStorage` 的 `dsh-plugin-categorized:overrides`），不改动 profile 里的任何文件，重开页面依然生效。
- **新装插件自动补中文**：以后安装的插件如果只有英文描述，宿主侧会自动调用默认模型翻出一个中文标题和一句话说明，写回该插件的 `locale/zh.json`，于是插件页上显示的就是中文。

## 使用

1. 打开「设置 → 插件」，点顶部的**分类**标签。
2. 找不着某个插件时，看「其他」分组——多半是内置规则还没覆盖到它。
3. 在那一行的下拉框里选一个分类；刷新后仍然保持。
4. 想还原，选「自动归类」。

## 边界与说明

- 只管显示与归类，不会安装、启用、卸载任何插件；这些仍在官方的「已安装」标签里做。
- 自动翻译只翻插件的**公开元数据**（包名与描述），不读取会话内容或项目文件；单个翻译失败会被跳过，不影响其他插件。
- 自动翻译要把中文写进插件自己的目录，因此对被 pnpm 安装进只读缓存、或没有 `dsh` 字段的普通 npm 包会直接跳过。
- 「其他」只是提示，不是错误：任何插件都可以被手动归到合适的分类里。
